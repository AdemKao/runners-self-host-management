# runnerctl v0.7.3 - persisted legacy queue stale grace

## Fixed

The legacy host-side queue now persists `RUNNERCTL_QUEUE_STALE_GRACE_SECONDS` in its queue configuration. Generated started hooks read that value at runtime instead of embedding the value from the command that generated the hook.

This prevents long-running Node.js, lint, test, and build jobs from being mistaken for stale work after the default 30-second grace period.

## Upgrade existing legacy queues

After upgrading an existing installation, drain the queue and wait for active jobs to finish before regenerating hooks:

```bash
export RUNNERCTL_QUEUE_STALE_GRACE_SECONDS=86400
runnerctl queue enable --max-concurrency 1
runnerctl queue status --json
```

`queue enable` resumes the gate after regenerating the hooks. Verify the status before allowing new production jobs.

`runnerctl scheduler` remains the preferred production mode because it keeps waiting jobs in GitHub's native `queued` state before runner assignment.
