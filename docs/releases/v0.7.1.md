# runnerctl v0.7.1 — Telegram Chat ID setup guidance

v0.7.1 is a documentation and setup-clarity patch for the Telegram integrations introduced in v0.6 and v0.7.

There is no scheduler, queue, runner-lifecycle, or Bot/API permission-model change in this patch.

## Why this patch exists

Telegram configuration requires a numeric **chat ID**, but users should not have to rely on third-party ID lookup bots or guess whether a personal chat or a group is the correct destination.

v0.7.1 adds a focused official-Bot-API workflow for finding the ID and explains the recommended deployment choices.

Full guides:

- English: `docs/telegram-chat-id.md`
- Traditional Chinese: `docs/telegram-chat-id.zh-TW.md`

## Recommended default

For one operator managing a self-hosted runner host, use a **private chat with the bot**.

Use a Telegram group or supergroup only when multiple trusted operators should share runner alerts or read-only runnerctl status queries.

A group can expose repository/runner state to everyone in that group, even though the v0.7 Bot/API controller is read-only.

## Find your private Chat ID

1. Create/configure your bot and obtain its bot token.
2. Open a private conversation with the bot.
3. Send a message such as `hello` or `/status`.
4. Call Telegram's official Bot API:

```bash
export RUNNERCTL_TELEGRAM_BOT_TOKEN='YOUR_BOT_TOKEN'

curl -fsSL \
  "https://api.telegram.org/bot${RUNNERCTL_TELEGRAM_BOT_TOKEN}/getUpdates"
```

5. Read the incoming message's `message.chat.id`:

```json
{
  "message": {
    "chat": {
      "id": 123456789,
      "type": "private"
    }
  }
}
```

Configure runnerctl with the returned value:

```bash
export RUNNERCTL_TELEGRAM_CHAT_ID='123456789'
export RUNNERCTL_TELEGRAM_ALLOWED_CHAT_IDS='123456789'
```

Do not publish the bot token in issues, logs, screenshots, shell history exports, or documentation.

## Group / supergroup IDs

Add the bot to the group and send a bot-visible message, then call `getUpdates` again.

Telegram group/supergroup IDs can be negative. Copy the ID exactly, including the leading minus sign:

```text
-1001234567890
```

Example configuration:

```bash
export RUNNERCTL_TELEGRAM_CHAT_ID='-1001234567890'
export RUNNERCTL_TELEGRAM_ALLOWED_CHAT_IDS='-1001234567890'
```

Multiple inbound allowed chats are comma-separated:

```bash
export RUNNERCTL_TELEGRAM_ALLOWED_CHAT_IDS='123456789,-1001234567890'
```

## `CHAT_ID` versus `ALLOWED_CHAT_IDS`

`RUNNERCTL_TELEGRAM_CHAT_ID`

- single destination used by the outbound Telegram notification provider;
- retained as the v0.6-compatible single-chat setting;
- also acts as the v0.7 inbound allowlist fallback when `RUNNERCTL_TELEGRAM_ALLOWED_CHAT_IDS` is unset.

`RUNNERCTL_TELEGRAM_ALLOWED_CHAT_IDS`

- explicit inbound read-only Bot/API allowlist;
- supports one or more comma-separated chats;
- preferred when multiple chats/groups are allowed to query runnerctl.

## Telegram long polling note

runnerctl's v0.7 Telegram controller uses Bot API `getUpdates` long polling.

Telegram webhook delivery and `getUpdates` long polling are alternative update-delivery modes for the same bot. If another application has configured a Telegram webhook for that bot, remove/disable that webhook before running:

```bash
runnerctl bot telegram run
```

The runnerctl HTTP listener used for LINE is unrelated to Telegram's Bot API webhook mode.

## Verification

Check credential presence without printing secrets:

```bash
runnerctl notify status --json
runnerctl bot doctor --json
```

Test outbound Telegram delivery:

```bash
runnerctl notify test --provider telegram
```

Test one inbound polling cycle:

```bash
runnerctl bot telegram run --once
```

## Compatibility

- No remote mutating Bot/API commands are added.
- Existing v0.7.0 Telegram allowlists continue to work unchanged.
- Existing `RUNNERCTL_TELEGRAM_CHAT_ID` notification configuration remains compatible.
- Scheduler, legacy queue, cleanup, runner registration, LINE, webhook notifications, and custom providers are unchanged.
- Python remains optional and is required only for `runnerctl bot ...` controller commands.

Official Telegram Bot API reference: <https://core.telegram.org/bots/api#getupdates>.
