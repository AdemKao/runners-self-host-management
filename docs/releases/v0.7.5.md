# runnerctl v0.7.5 - resolve the real GitHub worker ancestor

## Fixed

Legacy queue watchdogs now walk the hook process parent chain and record the actual GitHub `Runner.Worker` PID. GitHub can place workflow shell and hook-dispatch processes between `Runner.Worker` and the queue hook, so the direct parent is not a reliable worker identity.

Without this fix, an active slot could contain a short-lived dispatch-shell PID. Once that shell exited, stale-slot cleanup could incorrectly reclaim a slot belonging to a still-running workflow, or retain a dead slot and block the host queue.

## Upgrade

After installing v0.7.5, regenerate the legacy queue hooks:

```bash
export RUNNERCTL_QUEUE_STALE_GRACE_SECONDS=300
runnerctl queue enable --max-concurrency 1
runnerctl queue status --json
```

Before lowering stale grace on an existing installation, verify that any current slot either has a live recorded `Runner.Worker` PID or belongs to a completed/canceled job. The scheduler remains the preferred mode when workflows can request its routing label.
