# runnerctl v0.7.4 - preserve legacy queue worker identity

## Fixed

Legacy queue watchdogs now capture the real GitHub `Runner.Worker` parent PID before starting the legacy admission hook in the background. Previously, Bash could evaluate `PPID` inside the asynchronous child and persist the short-lived watchdog PID as the active slot owner.

That incorrect PID made a valid running job look stale as soon as the setup hook completed. On hosts using a long stale grace period, a canceled or interrupted job could then leave the host-wide queue blocked until manual recovery.

`runnerctl queue enable` also regenerates existing watchdog wrappers during upgrades, so an existing queue installation receives this fix without unregistering runners.

## Upgrade

After installing v0.7.4, regenerate the legacy queue hooks:

```bash
export RUNNERCTL_QUEUE_STALE_GRACE_SECONDS=300
runnerctl queue enable --max-concurrency 1
runnerctl queue status --json
```

If an old installation has a slot whose recorded worker PID is already gone, verify that no job is actively running on that slot before recovering the stale state. The scheduler remains the preferred mode when workflows can request its routing label.
