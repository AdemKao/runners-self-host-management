# runnerctl v0.8.0 - bounded storage admission and scoped maintenance

## Added

- `runnerctl storage inspect` reports free bytes, used percentage, and free
  inodes for any path without requiring a policy file.
- `runnerctl storage check` evaluates a policy file and exits `3` when a
  declared reserve is not met, for use as a pre-job gate.
- `runnerctl storage plan` and `runnerctl storage gc` provide a preview-first
  maintenance path for expired runner diagnostic logs and, when explicitly
  configured, garbage collection for one named buildx builder.
- `runnerctl agent --json` documents `storage inspect`, `storage check`,
  `storage plan`, and `storage gc` with their effect classes.
- `docs/storage.md` documents the policy format, exit codes, and rollout.

## Changed

- `cleanup status` no longer traverses workspace trees by default. Workspace
  sizes require the new `--sizes` flag with an optional `--timeout SECONDS`
  (default 5). Unmeasured sizes are reported as `null` with a `scan_status`
  value instead of an implicit `0`.
- The post-job cleanup hook is now implemented by the storage helper. It
  requires Python 3.8+, re-validates that the workspace is
  `<runner>/_work/<owner>/<repo>`, and bounds removal to 30 seconds.
- Manual `cleanup run RUNNER` requires `RUNNERCTL_CLEANUP_IDLE_CONFIRMED=1`,
  making the idle confirmation explicit instead of implicit.

## Safety limits

`runnerctl storage` has no global cleanup command. It never runs `docker system
prune`, `docker image prune`, `docker volume prune`, or `docker container prune`,
and never removes volumes, images, containerd content, package-manager caches,
workspaces, or backups. Builder GC is limited to one policy-named builder and
refuses the shared `default` and `desktop-linux` builders.

Log deletion retains the newest two `Runner_*.log` and two `Worker_*.log` files
per runner, verifies device, inode, size, and mtime immediately before unlinking,
writes an fsync'ed audit record for every removal, and fails closed on concurrent
maintenance.

Invalid policies are refused without echoing their contents.

## Upgrade

Existing hosts keep working without changes. New commands and flags are
additive, and cleanup continues to preserve package-manager caches, Docker data,
and runner logs.

To adopt admission checks:

```bash
runnerctl storage inspect --path /
runnerctl storage check --policy /etc/runnerctl/storage.json --json
runnerctl storage plan  --policy /etc/runnerctl/storage.json
```

To adopt log retention, add `log_retention_days` and the runner paths to the
policy, review the plan, then apply with an audit destination:

```bash
runnerctl storage gc --policy /etc/runnerctl/storage.json --apply --audit /var/log/runnerctl-storage.jsonl
```
